## 2. CÓ `upstream` remote không? — KHÔNG

```
$ git remote -v
origin  https://github.com/ultrabuilders/ultraworkers.git
```

Skill `sync-squashed-fork` fetch `upstream` và đọc `upstream/main`. Không có remote đó thì
script **không chạy được**, chứ không phải chạy sai. Lần sync trước phải đã từng thêm rồi xoá,
hoặc chạy tay ngoài script.

## 3. BẪY LỚN NHẤT: danh sách preserve mặc định sẽ XOÁ 950 file

Skill mặc định preserve **một** file: `COMPREHENSIVE_PLAN_FOR_OMP_UPGRADE.md`.
Nhưng thực tế thì:

- `milestone-1` có **951** file mà `origin/main` không có (kế hoạch, `.lavish`, `.lavish-wip`, `.beads`).
- Trên `origin/main` chỉ có `COMPREHENSIVE_PLAN_FOR_OMP_UPGRADE.md` và `AGENTS.md`.

`git read-tree --reset -u upstream/main` ghi đè index **và** worktree bằng cây upstream. File
fork-owned mà không preserve sẽ **biến mất khỏi worktree**; `--preserve` chỉ cứu được những
gì được liệt kê. Chạy skill với mặc định ở repo này là **mất toàn bộ kế hoạch**.

## 4. Cherry-pick không cần thiết — và có hại

`milestone-1` **là hậu duệ của `main`** (`git merge-base --is-ancestor main milestone-1` → true).
Không có chuyện "unrelated histories". Và so với `origin/main`, `milestone-1` khác **đúng 5 file
không phải tài liệu**, 97 dòng:

```

```

Đó là fix RCE (tắt `mcp.enableProjectConfig` mặc định) cùng test. Diff áp dụng sạch lên `main`
đã sync. Cherry-pick ~62 commit tài liệu để dựng lại kế hoạch là công việc nhiều hơn và rủi ro hơn,
đổi lấy không thêm gì.

**Cảnh báo đo sai trước đây:** lúc đầu có vẻ "1.208 file code khác", nhưng đó là code đến từ
commit sync, **không** phải từ milestone-1. Đếm đúng phải so với `origin/main`, không phải
so với `main` local.
